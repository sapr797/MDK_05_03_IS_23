## 1. Введение: Покрытие как инструмент, а не цель

В предыдущей лекции мы рассмотрели, как измерять покрытие кода с помощью `pytest-cov`. Однако измерение — это только первый шаг. Гораздо важнее **уметь увеличивать покрытие осмысленно** и **оценивать качество тестов** не только по проценту покрытых строк.

**Ключевая идея:** Покрытие — это не цель, а **инструмент для выявления пробелов в тестировании**. Слепое стремление к 100% покрытию может привести к:
- Бессмысленным тестам, которые проверяют тривиальный код.
- Сложным и хрупким тестам, которые трудно поддерживать.
- Игнорированию действительно важных сценариев.

## 2. Стратегии увеличения покрытия

### 2.1. Анализ отчёта покрытия

Прежде чем писать новые тесты, необходимо понять, **что именно** не покрыто.

**Пошаговый анализ:**

1. **Сгенерировать отчёт:** `pytest --cov=myproj --cov-report=term-missing`
2. **Идентифицировать файлы с низким покрытием:** Сортировка по проценту.
3. **Для каждого файла:**
   - Посмотреть на **красные строки** (не покрытые).
   - Определить, являются ли они критическими (основная логика) или второстепенными (обработка ошибок, редкие условия).
   - Составить план тестов.

**Пример анализа:**
Name Stmts Miss Cover Missing

utils/validators.py 45 20 56% 34-38, 45-48, 52-55, 60, 67
utils/parsers.py 30 5 83% 15-18
core/engine.py 120 15 87% 78, 89-93, 145-148

TOTAL 195 40 79%

text

**Приоритет:**
1. `validators.py` (56%) — **высокий приоритет**.
2. `engine.py` (87%) — **средний приоритет** (несколько блоков ошибок).
3. `parsers.py` (83%) — **низкий приоритет** (поправить мелкие пробелы).

### 2.2. Тестирование краевых случаев (Edge Cases)

Краевые случаи — это наиболее частая причина непокрытых ветвей.

**Пример:**

```python
def get_discount(amount, is_vip):
    if amount <= 0:
        return 0
    if is_vip:
        if amount > 1000:
            return 20
        return 10
    if amount > 5000:
        return 15
    return 5
Традиционные тесты (покрывают только счастливый путь):

python
def test_get_discount_vip_large():
    assert get_discount(1500, True) == 20
Тесты для краевых случаев (увеличивают покрытие):

python
def test_get_discount_zero_amount():
    assert get_discount(0, False) == 0
    assert get_discount(0, True) == 0

def test_get_discount_negative_amount():
    assert get_discount(-10, False) == 0

def test_get_discount_vip_small():
    assert get_discount(500, True) == 10

def test_get_discount_non_vip_large():
    assert get_discount(6000, False) == 15

def test_get_discount_non_vip_medium():
    assert get_discount(3000, False) == 5
2.3. Тестирование ветвей ошибок (Error Handling)
Обработка ошибок — это одна из самых часто непокрытых областей, потому что для их проверки нужно создать специальные условия.

Пример:

python
def process_payment(amount, method):
    if amount <= 0:
        raise ValueError("Amount must be positive")
    
    try:
        response = payment_gateway.charge(amount, method)
    except NetworkError:
        raise PaymentError("Network error during payment")
    except TimeoutError:
        raise PaymentError("Payment timeout")
    
    if response.status != "SUCCESS":
        raise PaymentError(f"Payment failed: {response.message}")
    
    return response.transaction_id
Тесты для ошибок:

python
def test_process_payment_negative_amount():
    with pytest.raises(ValueError, match="Amount must be positive"):
        process_payment(-10, "card")

def test_process_payment_network_error(mocker):
    mocker.patch('payment_gateway.charge', side_effect=NetworkError())
    with pytest.raises(PaymentError, match="Network error"):
        process_payment(100, "card")

def test_process_payment_timeout_error(mocker):
    mocker.patch('payment_gateway.charge', side_effect=TimeoutError())
    with pytest.raises(PaymentError, match="Payment timeout"):
        process_payment(100, "card")

def test_process_payment_status_failed(mocker):
    mock_response = Mock(status="FAILED", message="Insufficient funds")
    mocker.patch('payment_gateway.charge', return_value=mock_response)
    with pytest.raises(PaymentError, match="Payment failed"):
        process_payment(100, "card")
2.4. Тестирование ветвей с условиями (Branch Coverage)
Ветвевое покрытие (--cov-branch) показывает, проверены ли все ветви if/else, try/except, циклов и логических операторов.

Пример ветви, которую легко пропустить:

python
def get_status(code):
    if code == 200:
        return "OK"
    elif code == 404:
        return "Not Found"
    elif code == 500:
        return "Server Error"
    else:
        return "Unknown"
Тесты:

python
def test_get_status_200():
    assert get_status(200) == "OK"

def test_get_status_404():
    assert get_status(404) == "Not Found"

def test_get_status_500():
    assert get_status(500) == "Server Error"

def test_get_status_unknown():
    assert get_status(999) == "Unknown"
Сложные условия:

python
def validate_user(age, country, is_active):
    if age < 18 and country != "US":
        return False
    if age < 16:
        return False
    if not is_active:
        return False
    return True
Тесты должны покрывать все комбинации:

age < 18, country != "US"

age < 18, country == "US"

age < 16

age >= 18, not is_active

age >= 18, is_active

2.5. Тестирование циклов
Циклы требуют тестирования с разными размерами данных:

python
def process_batch(items, limit):
    result = []
    for item in items[:limit]:
        if item.is_valid():
            result.append(item.process())
    return result
Тесты:

python
def test_process_batch_empty():
    assert process_batch([], 10) == []

def test_process_batch_less_than_limit():
    items = [Mock(is_valid=True, process=lambda: "ok") for _ in range(3)]
    result = process_batch(items, 10)
    assert len(result) == 3

def test_process_batch_more_than_limit():
    items = [Mock(is_valid=True, process=lambda: "ok") for _ in range(20)]
    result = process_batch(items, 10)
    assert len(result) == 10

def test_process_batch_with_invalid_items():
    items = [
        Mock(is_valid=True, process=lambda: "ok"),
        Mock(is_valid=False),
        Mock(is_valid=True, process=lambda: "ok"),
    ]
    result = process_batch(items, 10)
    assert len(result) == 2
2.6. Использование # pragma: no cover осознанно
В некоторых случаях строки можно исключить из покрытия:

python
def my_function():
    if __debug__:
        # Отладочный код, не выполняется в production
        print("Debug mode")  # pragma: no cover
    
    # Код, который никогда не выполняется (например, защита от ошибок)
    raise RuntimeError("Unreachable")  # pragma: no cover
Когда это оправдано:

Код, который никогда не выполняется (недостижимые состояния).

Отладочный код (if __debug__).

Шаблонный код в абстрактных классах (raise NotImplementedError).

Обработка ошибок, которую невозможно воспроизвести в тестах.

3. Метрики качества тестов
Покрытие кода — это не единственная метрика. Для оценки качества тестов используются и другие показатели.

3.1. Основные метрики
Метрика	Что измеряет	Формула	Норма
Покрытие строк (Line Coverage)	% выполненных строк	(Выполненные строки / Все строки) * 100%	≥ 80%
Покрытие ветвей (Branch Coverage)	% выполненных ветвей	(Выполненные ветви / Все ветви) * 100%	≥ 70%
Покрытие функций (Function Coverage)	% вызванных функций	(Вызванные функции / Все функции) * 100%	≥ 90%
Покрытие требований (Requirements Coverage)	% протестированных требований	(Покрытые требования / Все требования) * 100%	≥ 95%
3.2. Ветвевое покрытие vs Строковое покрытие
python
def safe_divide(a, b):
    if b == 0:          # Ветвь 1: True
        return None     # Строка 1
    else:               # Ветвь 2: False
        return a / b    # Строка 2
Покрытие строк:

Тест с b != 0 покроет строки 1, 3 — 100% строк.

Но ветвь с b == 0 не проверена.

Покрытие ветвей:

Нужен тест с b == 0 и тест с b != 0 — 100% ветвей.

Вывод: Ветвевое покрытие — более строгая метрика.

3.3. Метрика MCDC (Modified Condition/Decision Coverage)
MCDC — это метрика, используемая в авиационных и медицинских стандартах (DO-178C, ISO 26262). Она требует, чтобы:

Каждое условие было протестировано как True, так и False.

Изменение одного условия при фиксированных остальных меняло общий результат.

Пример:

python
if (A and B) or C:
    # Действие
Требования MCDC:

Проверить A=True, B=True, C=False → True

Проверить A=False, B=True, C=False → False (A влияет на результат)

Проверить A=True, B=False, C=False → False (B влияет на результат)

Проверить A=True, B=True, C=True → True (C влияет на результат)

3.4. Сложность кода (Cyclomatic Complexity)
Цикломатическая сложность — это метрика, показывающая количество независимых путей выполнения в коде.

Как вычисляется:

V(G) = E - N + 2, где E — число рёбер, N — число вершин в графе потока управления.

Или проще: V(G) = количество ветвей + 1.

Нормы:

Сложность	Оценка	Рекомендация
1-10	Низкая	Хорошо
11-20	Средняя	Можно улучшить
21-50	Высокая	Нужно рефакторить
> 50	Критическая	Срочно рефакторить
Пример:

python
def process(data):  # V(G) = 1
    return data

def validate(x):    # V(G) = 3 (if + else + return)
    if x > 0:
        return True
    else:
        return False

def complex(x, y, z):  # V(G) = 5 (4 ветви + 1)
    if x > 0:
        if y > 0:
            return x + y
        else:
            return x - y
    else:
        if z > 0:
            return z * 2
        return 0
Как использовать:

Чем выше сложность, тем больше тестов нужно для полного покрытия.

Сложность > 20 — сигнал к рефакторингу.

3.5. Процент пропущенных тестов (Test Pass Rate)
python
pass_rate = (passed_tests / total_tests) * 100%
Значение:

95%+ — отлично.

85-95% — нормально (есть редкие flaky-тесты).

< 85% — тревожный сигнал.

4. Стратегии улучшения качества тестов
4.1. Тестирование "Обратного пути" (Negative Testing)
Проверка, что система корректно обрабатывает ошибки:

python
def test_negative_scenarios():
    # Невалидные входные данные
    with pytest.raises(ValueError):
        process(None)
    
    with pytest.raises(ValueError):
        process("invalid")
    
    # Отсутствие данных
    with pytest.raises(FileNotFoundError):
        load_file("not_exists.txt")
4.2. Тестирование с использованием мутационного анализа
Мутационное тестирование — это техника, при которой в код вносятся небольшие изменения (мутации), и проверяется, что тесты их находят.

Инструменты:

mutmut — мутационный тестировщик для Python.

cosmic-ray — альтернатива.

Как работает:

Вносятся изменения: a + b → a - b, if x > 0 → if x >= 0, return True → return False.

Запускаются тесты.

Если тесты не упали — мутация "выжила", значит тесты недостаточно чувствительны.

4.3. Тестирование с использованием property-based testing
Property-based testing — это техника, при которой тестируются свойства функций на случайных данных (Hypothesis).

python
from hypothesis import given, strategies as st

@given(st.integers(), st.integers())
def test_add_commutative(a, b):
    assert add(a, b) == add(b, a)

@given(st.integers(), st.integers())
def test_add_associative(a, b, c):
    assert add(add(a, b), c) == add(a, add(b, c))

@given(st.integers())
def test_add_identity(n):
    assert add(n, 0) == n
Преимущества:

Находит краевые случаи автоматически.

Проверяет свойства, а не конкретные значения.

6. Итоговый вывод по лекции
Увеличение покрытия кода и оценка качества тестов — это не разовая задача, а непрерывный процесс.

Ключевые тезисы для запоминания:

Анализируйте отчёт покрытия — смотрите не только на проценты, но и на конкретные непокрытые строки.

Приоритизируйте — сначала покрывайте критические файлы и ветви ошибок.

Тестируйте краевые случаи — они приносят больше пользы, чем проверка счастливых путей.

Используйте ветвевое покрытие (--cov-branch) — оно показывает реальные пробелы.

Следите за цикломатической сложностью — сложный код требует больше тестов.

Используйте метрики комплексно — покрытие, время выполнения, процент прохождения, MCDC.

Автоматизируйте контроль — включите --cov-fail-under в CI.

Помните: 100% покрытие — не гарантия качества. Смысл тестов важнее процентов.

Задание: Проанализировать существующий проект (класс ShoppingCart), определить пробелы в покрытии и написать тесты для увеличения покрытия до 90%+.

python
class ShoppingCart:
    def __init__(self):
        self.items = []
        self.discounts = []
        self.total = 0
        self.is_closed = False

    def add_item(self, item):
        if self.is_closed:
            raise ValueError("Cart is closed")
        if not item or not item.get('name'):
            raise ValueError("Invalid item")
        if item.get('price', 0) <= 0:
            raise ValueError("Price must be positive")
        self.items.append(item)
        self._recalculate_total()

    def remove_item(self, item_name):
        if self.is_closed:
            raise ValueError("Cart is closed")
        for i, item in enumerate(self.items):
            if item.get('name') == item_name:
                self.items.pop(i)
                self._recalculate_total()
                return True
        return False

    def apply_discount(self, discount_code):
        if self.is_closed:
            raise ValueError("Cart is closed")
        if discount_code == "SUMMER2025":
            if self.total > 5000:
                self.discounts.append(0.15)
            else:
                self.discounts.append(0.05)
        elif discount_code == "WELCOME":
            if len(self.items) > 5:
                self.discounts.append(0.20)
            else:
                self.discounts.append(0.10)
        else:
            raise ValueError(f"Unknown discount code: {discount_code}")
        self._recalculate_total()

    def checkout(self):
        if self.is_closed:
            raise ValueError("Cart is already closed")
        if not self.items:
            raise ValueError("Cannot checkout empty cart")
        if self.total <= 0:
            raise ValueError("Total must be positive")
        self.is_closed = True
        return {"total": self.total, "items": len(self.items)}

    def _recalculate_total(self):
        subtotal = sum(item.get('price', 0) for item in self.items)
        discount = 1 - min(1.0, sum(self.discounts))
        self.total = subtotal * discount

    def get_items(self):
        return self.items.copy()

    def get_total(self):
        return self.total
