## 1. Введение: Почему мокирование внешних зависимостей — это важно

В реальных проектах код редко работает в изоляции. Он зависит от:

- **Времени** — текущая дата, тайм-ауты, дедлайны.
- **Сети** — HTTP-запросы к внешним API.
- **Файловой системы** — чтение/запись файлов, проверка существования.
- **Базы данных** — запросы, транзакции.
- **Внешних сервисов** — платежные системы, почтовые серверы.

**Проблема:** Без мокирования тесты становятся:
- **Медленными** — каждый тест ждёт ответа от реального API.
- **Ненадёжными** — тесты падают из-за проблем сети или сервера.
- **Неизолированными** — один тест может влиять на другой.
- **Невоспроизводимыми** — невозможно протестировать краевые случаи (ошибки 500, тайм-ауты).

**Решение:** Заменять внешние зависимости на **моки (mocks)** — объекты-заглушки, которые имитируют поведение реальных зависимостей, но полностью контролируются в тесте.

## 2. Инструменты для мокирования в Python

### 2.1. `unittest.mock` — стандартная библиотека

Встроенный модуль `unittest.mock` (часть стандартной библиотеки Python) предоставляет мощные инструменты для создания моков.

**Основные компоненты:**

| Компонент | Описание |
|-----------|----------|
| `Mock` | Базовый класс для создания мок-объектов |
| `MagicMock` | Подкласс `Mock` с автоматической поддержкой магических методов (`__call__`, `__getitem__`, `__len__` и др.) |
| `patch` | Декоратор/контекстный менеджер для замены объекта на мок |
| `PropertyMock` | Мок для свойств (дескрипторов) |
| `AsyncMock` | Мок для асинхронных методов (Python 3.8+) |

### 2.2. `monkeypatch` — фикстура pytest

`monkeypatch` — это фикстура pytest, которая позволяет безопасно изменять атрибуты, переменные окружения и импорты во время теста.

**Основные методы:**

| Метод | Описание |
|-------|----------|
| `monkeypatch.setattr()` | Заменяет атрибут объекта |
| `monkeypatch.setenv()` | Заменяет переменную окружения |
| `monkeypatch.delenv()` | Удаляет переменную окружения |
| `monkeypatch.setitem()` | Заменяет элемент в словаре |
| `monkeypatch.chdir()` | Изменяет текущую директорию |

### 2.3. Когда что использовать?

| Сценарий | Рекомендуемый инструмент |
|----------|--------------------------|
| Мокирование методов объекта | `patch` или `monkeypatch.setattr` |
| Мокирование импортов | `patch` |
| Мокирование переменных окружения | `monkeypatch.setenv` |
| Мокирование файловой системы | `monkeypatch.chdir`, `monkeypatch.setattr` (os) |
| Мокирование времени | `monkeypatch.setattr` (datetime) |
| Мокирование HTTP-запросов | `patch` для `requests.get` / `httpx.AsyncClient` |
| Мокирование конфигурации | `monkeypatch.setitem` (для dict) |

## 3. Мокирование времени

### 3.1. Проблема

Функции, зависящие от текущего времени, могут вести себя по-разному в разные дни, что делает тесты нестабильными.

### 3.2. Решение: Подмена `datetime.now()` и `time.time()`

**Пример кода:**

```python
import datetime
import time

def is_weekend():
    today = datetime.datetime.now()
    return today.weekday() >= 5

def get_expiration_date(days):
    now = time.time()
    seconds = days * 24 * 60 * 60
    return now + seconds
Тесты с использованием monkeypatch:

python
import pytest
from datetime import datetime
import time

def test_is_weekend(monkeypatch):
    # Подмена datetime.now()
    class MockDatetime:
        @staticmethod
        def now():
            # Воскресенье (6)
            return datetime(2026, 9, 6)  # воскресенье
    
    monkeypatch.setattr('datetime.datetime', MockDatetime)
    assert is_weekend() is True

def test_is_weekend_weekday(monkeypatch):
    class MockDatetime:
        @staticmethod
        def now():
            return datetime(2026, 9, 7)  # понедельник
    
    monkeypatch.setattr('datetime.datetime', MockDatetime)
    assert is_weekend() is False

def test_get_expiration_date(monkeypatch):
    # Подмена time.time()
    monkeypatch.setattr('time.time', lambda: 1000.0)
    result = get_expiration_date(5)
    assert result == 1000.0 + 5 * 24 * 60 * 60
Тесты с использованием unittest.mock (patch):

python
from unittest.mock import patch
from datetime import datetime

@patch('datetime.datetime')
def test_is_weekend_with_patch(mock_datetime):
    mock_datetime.now.return_value = datetime(2026, 9, 6)  # воскресенье
    assert is_weekend() is True

@patch('datetime.datetime')
def test_get_expiration_date_with_patch(mock_datetime):
    # Более сложный: подмена time.time()
    with patch('time.time', return_value=1000.0):
        assert get_expiration_date(5) == 1000.0 + 5 * 24 * 60 * 60
3.3. Продвинутое мокирование: freezegun
Библиотека freezegun (сторонняя) предоставляет более удобный способ заморозки времени:

python
from freezegun import freeze_time

@freeze_time("2026-09-06")

    assert is_weekend() is True

@freeze_time("2026-09-07 12:00:00")

    assert is_weekend() is False
4. Мокирование HTTP-запросов
4.1. Проблема
Тесты, выполняющие реальные HTTP-запросы, медленные, ненадёжные и могут создавать побочные эффекты (например, отправлять реальные email).

4.2. Решение: подмена requests и httpx
Пример кода с requests:

python
import requests

def get_weather(city):
    url = f"https://api.weather.com/weather/{city}"
    response = requests.get(url)
    if response.status_code == 200:
        return response.json()
    raise Exception(f"Failed to get weather: {response.status_code}")
Тест с patch:

python
from unittest.mock import patch

@patch('requests.get')
def test_get_weather_success(mock_get):
    # Подготавливаем мок-ответ
    mock_response = Mock()
    mock_response.status_code = 200
    mock_response.json.return_value = {"temp": 25, "condition": "sunny"}
    mock_get.return_value = mock_response
    
    result = get_weather("Moscow")
    assert result["temp"] == 25
    assert result["condition"] == "sunny"
    mock_get.assert_called_once_with("https://api.weather.com/weather/Moscow")

@patch('requests.get')
def test_get_weather_error(mock_get):
    mock_response = Mock()
    mock_response.status_code = 404
    mock_get.return_value = mock_response
    
    with pytest.raises(Exception, match="Failed to get weather: 404"):
        get_weather("Moscow")
4.3. Продвинутое мокирование: responses и httpx_mock
Для более сложных сценариев (несколько запросов, параметры, заголовки) используются специальные библиотеки.

responses (для requests):

python
import responses

@responses.activate
def test_get_weather_with_responses():
    responses.add(
        responses.GET,
        "https://api.weather.com/weather/Moscow",
        json={"temp": 25, "condition": "sunny"},
        status=200
    )
    
    result = get_weather("Moscow")
    assert result["temp"] == 25
pytest_httpx (для httpx):

python
import httpx
from pytest_httpx import HTTPXMock

def test_httpx_with_mock(httpx_mock: HTTPXMock):
    httpx_mock.add_response(
        url="https://api.example.com/data",
        json={"key": "value"},
        status_code=200
    )
    
    response = httpx.get("https://api.example.com/data")
    assert response.json() == {"key": "value"}
5. Мокирование файловой системы
5.1. Проблема
Операции с файловой системой создают побочные эффекты (создание/удаление файлов), зависят от окружения и могут быть медленными.

5.2. Решение: подмена open, os и pathlib
Пример кода:

python
import os
import json
from pathlib import Path

def save_config(data, path):
    with open(path, 'w') as f:
        json.dump(data, f)

def load_config(path):
    if not os.path.exists(path):
        raise FileNotFoundError(f"Config file not found: {path}")
    with open(path, 'r') as f:
        return json.load(f)

def list_files(directory):
    return [f.name for f in Path(directory).iterdir() if f.is_file()]
Тесты с использованием monkeypatch:

python
def test_save_config(monkeypatch):
    mock_file = Mock()
    monkeypatch.setattr('builtins.open', mock_file)
    
    data = {"key": "value"}
    save_config(data, "/tmp/config.json")
    
    mock_file.assert_called_once_with("/tmp/config.json", 'w')
    handle = mock_file.return_value.__enter__.return_value
    handle.write.assert_called_once_with('{"key": "value"}')

def test_load_config_not_found(monkeypatch):
    monkeypatch.setattr('os.path.exists', lambda x: False)
    
    with pytest.raises(FileNotFoundError, match="Config file not found: /tmp/config.json"):
        load_config("/tmp/config.json")
5.3. Использование pathlib и pytest-mock
Тест с pytest-mock (обёртка над unittest.mock):

python
def test_list_files_with_pytest_mock(mocker):
    # Мокирование Path.iterdir()
    mock_path = mocker.patch('pathlib.Path.iterdir')
    mock_path.return_value = [
        Mock(name="file1.txt", is_file=lambda: True),
        Mock(name="file2.jpg", is_file=lambda: True),
        Mock(name="dir1", is_file=lambda: False),
    ]
    
    result = list_files("/tmp")
    assert result == ["file1.txt", "file2.jpg"]
5.4. Использование pyfakefs (специализированная библиотека)
pyfakefs создаёт полностью виртуальную файловую систему, не затрагивая реальную:

python
from pyfakefs.fake_filesystem_unittest import TestCase

class TestConfig(TestCase):
    def setUp(self):
        self.setUpPyfakefs()
    
    def test_save_and_load_config(self):
        # Работаем с виртуальной ФС
        data = {"key": "value"}
        save_config(data, "/tmp/config.json")
        
        # Проверяем, что файл создан
        assert os.path.exists("/tmp/config.json")
        
        # Загружаем
        loaded = load_config("/tmp/config.json")
        assert loaded == data
    
    def test_list_files(self):
        self.fs.create_file("/tmp/file1.txt")
        self.fs.create_file("/tmp/file2.jpg")
        self.fs.create_dir("/tmp/subdir")
        
        result = list_files("/tmp")
        assert sorted(result) == ["file1.txt", "file2.jpg"]

7. Практические паттерны мокирования
7.1. Паттерн "Сброс мока"
python
def test_with_mock_reset():
    mock = Mock()
    mock.method.return_value = 10
    assert mock.method() == 10
    
    mock.reset_mock()
    assert mock.method() == None  # Не вызывался после сброса
7.2. Паттерн "Сторонние эффекты" (side_effect)
python
def test_with_side_effect():
    mock = Mock()
    # Последовательность возвратов
    mock.method.side_effect = [10, 20, 30]
    assert mock.method() == 10
    assert mock.method() == 20
    assert mock.method() == 30
    
    # Выброс исключения
    mock.method.side_effect = ValueError("Test error")
    with pytest.raises(ValueError):
        mock.method()
7.3. Паттерн "Мокирование с помощью фабрики"
python
# В тестах часто нужно создавать моки с одинаковой конфигурацией
def create_mock_response(status_code=200, json_data=None):
    mock = Mock()
    mock.status_code = status_code
    mock.json.return_value = json_data or {}
    return mock

def test_with_factory():
    mock_get = Mock()
    mock_get.return_value = create_mock_response(200, {"key": "value"})
    
    with patch('requests.get', mock_get):
        response = requests.get("https://api.example.com")
        assert response.status_code == 200
        assert response.json() == {"key": "value"}
8. Сравнение подходов
Инструмент	Когда использовать	Преимущества	Недостатки
unittest.mock	В любом тесте	Мощный, гибкий, встроенный	Много кода, сложный API
pytest-mock	В тестах с фикстурами	Удобный синтаксис, интеграция с pytest	Зависимость от плагина
monkeypatch	Для простых подмен (время, окружение)	Безопасен, автоматический откат	Ограниченные возможности
freezegun	Для работы со временем	Простой синтаксис, изоляция	Только время
responses	Для HTTP-запросов	Удобный DSL, проверка запросов	Только requests
pyfakefs	Для файловой системы	Полная изоляция	Только ФС, медленный
9. Итоговый вывод по лекции
Мокирование внешних зависимостей — это фундаментальный навык, который превращает нестабильные интеграционные тесты в быстрые и надёжные модульные.

Ключевые тезисы для запоминания:

Мокирование времени: подмена datetime.now() и time.time() с помощью monkeypatch или freezegun.

Мокирование HTTP: подмена requests.get с помощью patch или специализированных библиотек (responses, pytest_httpx).

Мокирование ФС: подмена open, os.path.exists, pathlib с помощью monkeypatch или pyfakefs.

Основные инструменты: unittest.mock (базовый), monkeypatch (фикстура), pytest-mock (удобная обёртка).

Паттерны: side_effect, return_value, PropertyMock, фабрики для создания моков.

Правило: Никогда не обращайтесь к реальной сети, времени или файлам в модульных тестах.

Задание: Написать модульные тесты для класса BackupService, который зависит от времени, файловой системы и HTTP-запросов.

Код для тестирования:

python
import os
import datetime
import requests
import json
from pathlib import Path

class BackupService:
    def __init__(self, backup_dir, api_url):
        self.backup_dir = Path(backup_dir)
        self.api_url = api_url
        self._ensure_backup_dir()
    
    def _ensure_backup_dir(self):
        if not self.backup_dir.exists():
            self.backup_dir.mkdir(parents=True)
    
    def create_backup(self, data):
        timestamp = datetime.datetime.now().strftime("%Y%m%d_%H%M%S")
        filename = f"backup_{timestamp}.json"
        filepath = self.backup_dir / filename
        
        with open(filepath, 'w') as f:
            json.dump(data, f)
        
        return str(filepath)
    
    def send_backup(self, filepath):
        if not os.path.exists(filepath):
            raise FileNotFoundError(f"Backup file not found: {filepath}")
        
        with open(filepath, 'r') as f:
            data = json.load(f)
        
        try:
            response = requests.post(
                self.api_url,
                json=data,
                timeout=5
            )
            response.raise_for_status()
            return response.json()
        except requests.exceptions.Timeout:
            raise Exception("Backup upload timed out")
        except requests.exceptions.RequestException as e:
            raise Exception(f"Backup upload failed: {e}")
    
    def backup_and_send(self, data):
        filepath = self.create_backup(data)
        result = self.send_backup(filepath)
        return result
