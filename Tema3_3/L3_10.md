## 1. Введение: Почему тестирование исключений — это важно

Исключения (exceptions) — это не просто механизм обработки ошибок, а **неотъемлемая часть контракта** любого метода или функции. Корректная обработка исключительных ситуаций — признак зрелого и надёжного программного обеспечения.

**Цели тестирования исключений:**

1. **Проверка контракта:** Убедиться, что при нарушении предусловий действительно выбрасывается ожидаемое исключение.
2. **Проверка сообщений:** Убедиться, что сообщение исключения содержит полезную информацию для пользователя.
3. **Проверка атрибутов:** Убедиться, что пользовательские исключения передают дополнительные данные (код ошибки, причина, контекст).
4. **Проверка цепочек исключений:** Убедиться, что причина (`__cause__`) и контекст (`__context__`) корректно передаются.

## 2. Основы: `pytest.raises` как контекстный менеджер

Основной инструмент для тестирования исключений в `pytest` — контекстный менеджер `pytest.raises`. Он позволяет выполнить блок кода и проверить, что он выбрасывает ожидаемое исключение.

### 2.1. Базовое использование

Проверка, что код выбрасывает определённый тип исключения:

```python
import pytest

def divide(a, b):
    if b == 0:
        raise ValueError("Division by zero")
    return a / b

def test_divide_by_zero():
    with pytest.raises(ValueError):
        divide(10, 0)
Если divide(10, 0) выбрасывает ValueError, тест проходит. Если исключение не выброшено или выброшено другое исключение — тест падает.

2.2. Получение объекта исключения: ExceptionInfo
Иногда недостаточно просто проверить тип исключения. Нужно проверить его сообщение, атрибуты или причину.

Для этого pytest.raises возвращает объект ExceptionInfo, который содержит всю информацию о перехваченном исключении .

python
def test_divide_by_zero_with_info():
    with pytest.raises(ValueError) as exc_info:
        divide(10, 0)
    
    # Основные атрибуты ExceptionInfo
    assert exc_info.type is ValueError          # Тип исключения
    assert exc_info.value.args[0] == "Division by zero"  # Сообщение
    assert "Division by" in str(exc_info.value) # Проверка сообщения
Основные атрибуты ExceptionInfo:

Атрибут	Описание
excinfo.type	Класс перехваченного исключения
excinfo.value	Сам объект исключения (экземпляр)
excinfo.tb	Сырой traceback
excinfo.traceback	Traceback в удобном для анализа формате
2.3. Проверка сообщения с помощью match
Аргумент match позволяет проверить, что сообщение исключения соответствует регулярному выражению .

python
def test_divide_by_zero_match():
    with pytest.raises(ValueError, match=".*division by zero.*"):
        divide(10, 0)
match использует re.search, поэтому можно использовать как простые строки, так и регулярные выражения. Например, match="123" сработает для сообщения "Exception 123 raised" .

3. Углублённые техники: Проверка атрибутов исключений
3.1. Проверка пользовательских исключений
Когда вы определяете собственные классы исключений с дополнительными полями, стандартный match не поможет. Нужно получить объект исключения через exc_info.value и проверить его атрибуты напрямую .

python
class CustomException(ValueError):
    def __init__(self, message, error_code, details=None):
        super().__init__(message)
        self.error_code = error_code
        self.details = details or {}

def process_data(data):
    if not data:
        raise CustomException("Data is empty", 1001, {"field": "data"})
    return data

def test_custom_exception_attributes():
    with pytest.raises(CustomException) as exc_info:
        process_data(None)
    
    # Проверка атрибутов через exc_info.value
    assert exc_info.value.error_code == 1001
    assert exc_info.value.details["field"] == "data"
    assert "empty" in str(exc_info.value)
Важно: Всегда выполняйте проверку атрибутов после выхода из контекстного менеджера pytest.raises, используя объект exc_info.value .

3.2. Пример: Проверка валидационных ошибок (Pydantic)
При работе с Pydantic или подобными валидаторами, проверка атрибутов исключения — стандартная практика :

python
from pydantic import BaseModel, ValidationError, ConfigDict

class ForbiddenExtra(BaseModel):
    model_config = ConfigDict(extra='forbid')
    foo: str = 'whatever'

def test_forbidden_extra_fails():
    with pytest.raises(ValidationError) as exc_info:
        ForbiddenExtra(foo='ok', bar='wrong', spam='xx')
    
    # Проверка деталей валидации через атрибуты исключения
    errors = exc_info.value.errors(include_url=False)
    assert len(errors) == 2
    assert errors[0]['type'] == 'extra_forbidden'
    assert errors[0]['loc'] == ('bar',)
3.3. Точное совпадение типа исключения
По умолчанию pytest.raises считает успехом выброс любого подкласса ожидаемого исключения (как except в Python) . Например, если ожидается RuntimeError, а выбрасывается NotImplementedError (его подкласс), тест пройдёт.

Это может привести к ложноположительным тестам, если код выбрасывает неожиданный подкласс.

Решение: Проверять точное совпадение типа :

python
def test_exact_exception_type():
    with pytest.raises(RuntimeError) as exc_info:
        # Код, который может выбросить NotImplementedError
        raise NotImplementedError("Some message")
    
    # Точная проверка типа (не подкласс)
    assert exc_info.type is RuntimeError  # Тест упадёт!
4. Углублённые техники: Цепочки исключений (__cause__ и __context__)
Python позволяет создавать цепочки исключений, используя raise ... from ... (__cause__) или автоматически сохраняя контекст (__context__).

4.1. Текущая поддержка в pytest
На данный момент в pytest нет встроенного механизма для проверки причины (__cause__) или контекста (__context__) исключения через match . Однако можно использовать стандартные средства Python.

Проверка причины (__cause__):

python
def i_raise_a_causing_exception():
    try:
        raise ValueError("i'm a causing exception")
    except ValueError as e:
        raise RuntimeError("i'm an exception") from e

def test_cause_exception():
    with pytest.raises(RuntimeError) as exc_info:
        i_raise_a_causing_exception()
    
    # Доступ к причине через __cause__
    cause = exc_info.value.__cause__
    assert isinstance(cause, ValueError)
    assert str(cause) == "i'm a causing exception"
Проверка контекста (__context__):

python
def i_raise_a_context_exception():
    try:
        raise ValueError("This is the first context")
    finally:
        raise ValueError("This is the second context")

def test_context_exception():
    with pytest.raises(ValueError) as exc_info:
        i_raise_a_context_exception()
    
    # Доступ к контексту через __context__
    context = exc_info.value.__context__
    assert isinstance(context, ValueError)
    assert str(context) == "This is the first context"
4.2. Альтернативный подход (предложение в разработке)
В сообществе pytest обсуждается возможность добавления матчеров для проверки причин и контекста . На данный момент рекомендуется использовать прямой доступ к атрибутам __cause__ и __context__.

5. Сравнение pytest.raises и @pytest.mark.xfail(raises=...)
Характеристика	pytest.raises	@pytest.mark.xfail(raises=...)
Назначение	Проверка, что код выбрасывает ожидаемое исключение	Документирование известной проблемы (баг)
Ожидание	Исключение должно быть выброшено	Исключение может быть выброшено
Результат	PASS → исключение выброшено, FAIL → не выброшено	XPASS → исключение выброшено, XFAIL → не выброшено
Применение	Тестирование собственного кода	Документирование неисправленных багов 
python
# Тестирование собственного кода — используем pytest.raises
def test_my_exception():
    with pytest.raises(ValueError):
        my_function()

# Документирование неисправленного бага — используем xfail
@pytest.mark.xfail(raises=IndexError)
def test_known_bug():
    buggy_function()

Тестирование исключений — это не просто проверка, что код упал. Это проверка контракта метода, включая:

Сообщение исключения (match).

Атрибуты пользовательского исключения (exc_info.value).

Ключевые тезисы для запоминания:

pytest.raises — основной инструмент для проверки исключений.

ExceptionInfo даёт доступ к полной информации об исключении.

match проверяет сообщение исключения через регулярное выражение.

Для проверки атрибутов используйте exc_info.value.

pytest.raises принимает любой подкласс ожидаемого исключения — для точной проверки используйте exc_info.type is.

Для цепочек исключений используйте прямой доступ к __cause__ и __context__.

@pytest.mark.xfail(raises=...) используется для документирования известных багов.

Класс:

python
class OrderValidationError(Exception):
    def __init__(self, message, field, code):
        super().__init__(message)
        self.field = field
        self.code = code

class Order:
    def __init__(self, customer_id, amount, items):
        self.customer_id = customer_id
        self.amount = amount
        self.items = items
    
    def validate(self):
        if self.customer_id is None:
            raise OrderValidationError("Customer ID is required", "customer_id", 400)
        if self.amount <= 0:
            raise OrderValidationError("Amount must be positive", "amount", 400)
        if not self.items:
            raise OrderValidationError("Order must have at least one item", "items", 400)
        return True
    
    def process(self):
        try:
            self.validate()
            # Логика обработки заказа
        except OrderValidationError as e:
            # Логирование и ре-рейз
            raise RuntimeError("Order processing failed") from e
