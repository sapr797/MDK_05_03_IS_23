## 1. Введение: Зачем нужно измерять покрытие кода

Покрытие кода (code coverage) — это метрика, показывающая, какая часть исходного кода была выполнена во время тестирования. Это не цель, а **инструмент**, который помогает:

| Задача | Как помогает покрытие |
|--------|----------------------|
| **Поиск пробелов в тестах** | Показывает, какие строки, ветви или функции не проверяются |
| **Оценка качества тестирования** | Даёт количественную метрику (например, "покрытие 85%") |
| **Выявление мёртвого кода** | Код, который никогда не выполняется, можно удалить |
| **Приоритизация тестов** | Сначала покрываем критичные, но непокрытые участки |
| **Контроль в CI/CD** | Можно требовать, чтобы покрытие не падало ниже порога |

**Важно:** Покрытие **не гарантирует** качество тестов. Можно получить 100% покрытие, не проверив ни одного краевого случая. Но низкое покрытие — это **надёжный сигнал**, что тестов недостаточно.

## 2. pytest-cov: Инструмент для измерения покрытия

### 2.1. Что такое pytest-cov

`pytest-cov` — это плагин для pytest, который интегрирует библиотеку `coverage.py` и добавляет удобные возможности [citation:1]:

- **Автоматическое измерение покрытия** во время выполнения тестов.
- **Поддержка распределённого тестирования** (`pytest-xdist`).
- **Формирование отчётов** в разных форматах (терминал, HTML, XML, JSON, LCOV, Markdown) [citation:11].
- **Проверка порога покрытия** (`--cov-fail-under`) для CI/CD [citation:5].
- **Контекстное покрытие** (привязка покрытия к конкретным тестам).

3. Форматы отчётов покрытия
3.1. Терминальные отчёты
bash
# Стандартный отчёт (только проценты)
pytest --cov=myproj --cov-report=term

# Отчёт с пропущенными строками (--cov-report=term-missing)
pytest --cov=myproj --cov-report=term-missing
Вывод:

text
Name                 Stmts   Miss  Cover   Missing
--------------------------------------------------
myproj/core.py          50      5    90%   24-26, 99, 149
myproj/utils.py         30      2    93%   87, 102
--------------------------------------------------
TOTAL                   82      7    91%
bash
# Пропуск полностью покрытых файлов
pytest --cov=myproj --cov-report="term:skip-covered"
3.2. HTML-отчёт
bash
# Генерация HTML-отчёта в папке htmlcov
pytest --cov=myproj --cov-report=html
Особенности HTML-отчёта :

Каждый файл отображается на отдельной странице.

Исходный код подсвечен: зелёным — выполненные строки, красным — пропущенные.

Можно кликать по файлам и просматривать детали.

Сохранение в указанную директорию:

bash
pytest --cov=myproj --cov-report=html:reports/coverage_html
3.3. XML-отчёт
bash
# Генерация XML-отчёта (coverage.xml)
pytest --cov=myproj --cov-report=xml
Назначение: Используется для интеграции с CI/CD (GitLab, Jenkins), инструментами статического анализа и обзорными панелями.

bash
# Сохранение в указанный файл
pytest --cov=myproj --cov-report=xml:reports/coverage.xml
3.4. JSON-отчёт
bash
pytest --cov=myproj --cov-report=json
Назначение: Машиночитаемый формат для автоматической обработки, генерации дашбордов и кастомных сценариев анализа.

3.5. Markdown-отчёт
bash
pytest --cov=myproj --cov-report=markdown

# Для добавления в GitHub Actions Summary
pytest --cov=myproj --cov-report=markdown-append:$GITHUB_STEP_SUMMARY
3.6. LCOV-отчёт
bash
pytest --cov=myproj --cov-report=lcov
Назначение: Совместимость с инструментами, использующими формат LCOV (например, Coveralls, Codecov).

3.7. Одновременная генерация нескольких отчётов
bash
pytest --cov=myproj \
       --cov-report=term-missing \
       --cov-report=html:reports/html \
       --cov-report=xml:reports/coverage.xml \
       --cov-report=json:reports/coverage.json \
       --cov-report=markdown:reports/coverage.md
Если вы указали хотя бы один --cov-report, стандартный терминальный отчёт (term) не добавляется автоматически .

4. Дополнительные возможности pytest-cov
4.1. Ветвевое покрытие (Branch Coverage)
По умолчанию измеряется только покрытие строк. Ветвевое покрытие учитывает, были ли выполнены все ветви условных операторов (if/else, try/except, циклы).

bash
pytest --cov=myproj --cov-branch --cov-report=term-missing
Зачем: Даже при 100% покрытии строк могут остаться непроверенными ветви. Например, if x > 0 может быть выполнено только с x=1, а x=0 — нет.

4.2. Установка порога покрытия (--cov-fail-under)
bash
pytest --cov=myproj --cov-fail-under=80
Если общее покрытие ниже 80%, тесты завершаются с кодом ошибки 2 .

Полезно для CI/CD: можно блокировать слияние кода, который снижает покрытие.

4.3. Контекстное покрытие (--cov-context=test)
coverage.py 5.0+ поддерживает запись контекста выполнения, что позволяет привязать покрытие к конкретным тестам .

bash
pytest --cov=myproj --cov-context=test
Результат: В HTML-отчёте можно увидеть, какие именно тесты покрывают каждую строку .

Пример контекста в отчёте:

text
test_core.py::test_process_order|run
test_core.py::test_calculate_total|run
test_utils.py::test_validate_email|run
Визуализация: Добавьте в .coveragerc:

ini
[html]
show_contexts = True
4.4. Исключение файлов из отчёта
Через CLI:

bash
# Исключение тестовых файлов из отчёта
pytest --cov=myproj --cov-omit="*test*"
Через .coveragerc:

ini
[run]
omit =
    */tests/*
    */venv/*
    */migrations/*

[report]
omit =
    */tests/*
    */venv/*
    */migrations/*
4.5. Отключение покрытия (--no-cov)
Позволяет временно отключить измерение покрытия (например, для отладки):

bash
pytest --no-cov
4.6. Добавление опций в конфигурацию pytest
Можно настроить pytest-cov в pyproject.toml:

toml
[tool.pytest.ini_options]
addopts = [
    "--cov=myproj",
    "--cov-report=html:reports/coverage_html",
    "--cov-report=term-missing",
    "--cov-fail-under=80"
]
5. Анализ отчётов: Как находить пробелы
5.1. Пошаговая стратегия анализа
Шаг 1. Сгенерировать HTML-отчёт:

bash
pytest --cov=myproj --cov-report=html
Шаг 2. Открыть htmlcov/index.html в браузере.

Шаг 3. Обратить внимание на файлы с низким покрытием (красные/жёлтые).

Шаг 4. Классификация пробелов:

Тип пробела	Как выглядит	Что делать
Непокрытые строки в функциях	Красные строки внутри зелёного блока	Добавить тесты для краевых случаев
Целый файл не покрыт	Весь файл красный	Написать базовые тесты для модуля
Ветви не покрыты	В терминальном отчёте видно невыполненные ветви	Добавить тесты для всех if/else
Игнорируемый код	Строки с # pragma: no cover	Проверить, действительно ли их можно игнорировать
5.2. Пример анализа
bash
pytest --cov=myproj --cov-report=term-missing
Вывод:

text
Name                 Stmts   Miss  Cover   Missing
--------------------------------------------------
myproj/__init__          2      0   100%
myproj/order.py         45      3    93%   67, 89, 102
myproj/payment.py       30      12   60%   45-48, 55-58, 62, 70-73
myproj/email.py         18      15   16%   30-50
--------------------------------------------------
TOTAL                   95      30   68%
Анализ:

email.py (16% покрытия) — критический пробел: нужно срочно добавить тесты для отправки email.

payment.py (60%) — средний приоритет: непокрыты сценарии ошибок оплаты.

order.py (93%) — низкий приоритет: осталось покрыть 3 строки.

5.3. Приоритизация тестов
Приоритет	Критерий	Действие
Высокий	Файлы с покрытием < 50%	Написать базовые тесты для всего модуля
Средний	Файлы с покрытием 50-80%	Добавить тесты для краевых случаев и ошибок
Низкий	Файлы с покрытием > 80%	Добить оставшиеся строки (обычно обработка ошибок)
6. Интеграция с CI/CD
6.1. GitHub Actions
yaml
- name: Run tests with coverage
  run: |
    pytest --cov=myproj --cov-report=xml --cov-report=term-missing
  
- name: Upload coverage to Codecov
  uses: codecov/codecov-action@v3
  with:
    files: ./coverage.xml

yaml
coverage:
  script:
    - pytest --cov=myproj --cov-report=term-missing --cov-fail-under=80
    - coverage report
  coverage: '/TOTAL.+\s(\d+\.\d+%)/'
  artifacts:

      coverage_report:
        coverage_format: cobertura
        path: coverage.xml
6.3. Требование порога покрытия
bash
pytest --cov=myproj --cov-fail-under=80
Если покрытие < 80%, процесс завершится с ошибкой, и CI/CD упадёт.

7.4. Исключение строк из покрытия (# pragma: no cover)
python
def my_function():
    # Эта строка будет исключена из покрытия
    if __debug__:  # pragma: no cover
        print("Debug mode")

    # Исключение целого блока
    try:
        result = process()
    except Exception as e:  # pragma: no cover
        log_error(e)
8. Частые ошибки при работе с покрытием
Ошибка	Описание	Решение
Покрытие 100%, но есть баги	Проверяются только счастливые пути	Добавить негативные тесты
Медленные тесты	Генерация отчётов замедляет выполнение	В CI: использовать только xml или json, без html
Загрязнение данными	Данные от предыдущих запусков суммируются	Использовать --cov-append осознанно
Игнорирование ветвей	100% строк, но непроверенные if/else	Включить --cov-branch
Слишком низкий порог	--cov-fail-under ниже реального покрытия	Установить целевой порог для улучшения
9. Итоговый вывод по лекции
Измерение покрытия кода с помощью pytest-cov — это не просто метрика, а инструмент управления качеством тестирования.

Ключевые тезисы для запоминания:

pytest-cov расширяет pytest для измерения покрытия кода.

Основные форматы отчётов: term, html, xml, json, markdown, lcov.

Ветвевое покрытие (--cov-branch) показывает, проверены ли все ветви if/else.

Порог покрытия (--cov-fail-under) позволяет блокировать CI при недостаточном покрытии.

Контекстное покрытие (--cov-context=test) привязывает строки к конкретным тестам.

Анализ отчётов должен быть системным: сначала файлы с низким покрытием, затем ветви, затем детали.

100% покрытие — не цель. Важно покрыть критические сценарии и обработку ошибок.

# calculator.py
class Calculator:
    def add(self, a, b):
        return a + b

    def subtract(self, a, b):
        return a - b

    def multiply(self, a, b):
        return a * b

    def divide(self, a, b):
        if b == 0:
            raise ValueError("Division by zero")
        return a / b

    def power(self, a, b):
        if b < 0:
            raise ValueError("Negative exponent not supported")
        return a ** b

    def is_prime(self, n):
        if n < 2:
            return False
        for i in range(2, int(n ** 0.5) + 1):
            if n % i == 0:
                return False
        return True

    def factorial(self, n):
        if n < 0:
            raise ValueError("Factorial not defined for negative numbers")
        if n == 0:
            return 1
        result = 1
        for i in range(1, n + 1):
            result *= i
        return result
