## 1. Введение: Почему состояние объектов требует особого внимания

В объектно-ориентированных системах данные (состояние) и поведение (методы) объединены внутри объектов. В отличие от процедурного подхода, где данные пассивны, в ООП объекты **активно управляют своим состоянием**. Именно это управление состоянием становится источником многих трудноуловимых дефектов.

**Ключевая проблема:** Метод может возвращать корректный результат, но при этом **некорректно изменять состояние объекта**, что приведёт к ошибкам в будущих вызовах. Традиционное тестирование, проверяющее только выходные значения методов, часто пропускает такие дефекты.

**Пример скрытой проблемы:**

```java
public class BankAccount {
    private double balance;
    private boolean isBlocked;
    private int failedAttempts;
    
    public void withdraw(double amount) {
        // Логика работает, но состояние меняется некорректно
        if (isBlocked) {
            failedAttempts++; // Ошибка: счётчик растёт даже при блокировке
            return;
        }
        if (amount > balance) {
            failedAttempts++;
            return;
        }
        balance -= amount;
        failedAttempts = 0;
    }
}
Метод withdraw() работает и возвращает корректные результаты, но состояние объекта (поля failedAttempts и isBlocked) изменяется неправильно. Это приведёт к ошибкам в будущем.

2. Базовые понятия
2.1. Состояние объекта (Object State)
Определение: Состояние объекта — это совокупность значений всех его атрибутов (полей) в определённый момент времени.

Характеристики состояния:

Статическое состояние — значения полей объекта в конкретный момент.

Динамическое состояние — изменение значений полей во времени под воздействием вызовов методов.

Пример состояния объекта BankAccount:

text
{
    accountNumber: "1234567890",
    balance: 15000.00,
    currency: "RUB",
    isBlocked: false,
    failedAttempts: 0,
    lastTransactionDate: "2026-09-01"
}
2.2. Инварианты класса (Class Invariants)
Определение: Инвариант класса — это логическое условие (утверждение), которое должно быть истинно для всех корректных состояний объекта в любой момент времени между вызовами его методов.

Простыми словами: Инвариант — это правило, которое никогда не должно нарушаться в течение жизни объекта.

Примеры инвариантов:

Класс	Инвариант
BankAccount	balance >= 0 (баланс не может быть отрицательным)
BankAccount	Если isBlocked == true, то failedAttempts >= 3
Order	totalPrice == sum(item.price * item.quantity)
Date	day >= 1 && day <= 31
Triangle	a + b > c && a + c > b && b + c > a
Роль инвариантов в тестировании:

Инварианты определяют критерии корректности состояния объекта.

Нарушение инварианта — это дефект, который должен быть обнаружен.

Инварианты служат тестовыми оракулами для проверки состояния.

2.3. Предусловия и постусловия (Preconditions & Postconditions)
В дополнение к инвариантам, которые действуют всё время, существуют предусловия и постусловия для отдельных методов.

Понятие	Описание	Пример
Предусловие	Условие, которое должно быть истинно до вызова метода.	amount > 0 для метода deposit()
Постусловие	Условие, которое должно быть истинно после вызова метода.	balance == old_balance + amount для метода deposit()
Связь с инвариантами:

Предусловия и постусловия являются временными ограничениями.

Инварианты должны выполняться до и после выполнения метода.

Метод может временно нарушать инвариант внутри себя, но должен восстановить его перед выходом.

3. Техники тестирования состояния объектов
3.1. Тестирование на основе инвариантов (Invariant-Based Testing)
Идея: Создать тесты, которые проверяют, что все инварианты класса сохраняются после каждого вызова метода.

Алгоритм:

Идентифицировать инварианты класса (из спецификации, из кода, из бизнес-правил).

Реализовать проверку инвариантов в виде отдельного метода checkInvariants().

Вставить вызовы проверки в тесты после каждого шага.

Выполнить тесты и убедиться, что ни один инвариант не нарушен.

Пример реализации проверки инвариантов:

java
public class BankAccount {
    private double balance;
    private boolean isBlocked;
    private int failedAttempts;
    
    // Метод проверки инвариантов
    private void checkInvariants() {
        // Инвариант 1: баланс не может быть отрицательным
        assert balance >= 0 : "Баланс не может быть отрицательным";
        
        // Инвариант 2: если заблокирован, то попыток >= 3
        if (isBlocked) {
            assert failedAttempts >= 3 : "Блокировка при попытках < 3";
        }
        
        // Инвариант 3: если попыток >= 3, то объект заблокирован
        if (failedAttempts >= 3) {
            assert isBlocked : "Попыток >= 3, но объект не заблокирован";
        }
        
        // Инвариант 4: баланс не может превышать лимит
        assert balance <= 1000000 : "Превышен лимит баланса";
    }
}
3.2. Техника "Состояние-действие-состояние" (State-Action-State)
Идея: Каждый тест структурируется как последовательность:

Состояние (State): Проверка начального состояния объекта.

Действие (Action): Вызов тестируемого метода.

Состояние (State): Проверка конечного состояния объекта.

Структура теста:

text
// 1. State - проверка начального состояния
assertEquals(0, account.getBalance());
assertFalse(account.isBlocked());

// 2. Action - выполнение действия
account.deposit(1000);

// 3. State - проверка конечного состояния
assertEquals(1000, account.getBalance());
assertEquals(account.getOldBalance() + 1000, account.getBalance());
checkInvariants(); // Инварианты должны сохраниться
Преимущества:

Чёткая структура тестов.

Проверяется не только результат, но и состояние.

Легко локализовать ошибку (начальное состояние, действие или конечное состояние).

3.3. Тестирование с использованием контрактов (Contract Testing)
Идея: Формально специфицировать предусловия, постусловия и инварианты с помощью контрактного программирования (Design by Contract, DbC), а затем автоматически проверять их выполнение.

Реализация контрактов в Java (с использованием assert или библиотек):

java
public class BankAccount {
    private double balance;
    
    /**
     * @pre amount > 0 (сумма должна быть положительной)
     * @post balance == old(balance) + amount
     * @invariant balance >= 0
     */
    public void deposit(double amount) {
        // Проверка предусловия
        assert amount > 0 : "Сумма должна быть положительной";
        
        double oldBalance = balance;
        balance += amount;
        
        // Проверка постусловия
        assert balance == oldBalance + amount : "Баланс изменился некорректно";
        
        // Проверка инварианта
        assert balance >= 0 : "Инвариант нарушен";
    }
}
Инструменты для контрактного программирования:

Инструмент	Язык	Описание
Java Modeling Language (JML)	Java	Формальная спецификация контрактов с аннотациями
Code Contracts	C#	Встроенная поддержка контрактов в .NET
Eiffel	Eiffel	Встроенная поддержка DbC на уровне языка
PyContracts	Python	Библиотека для контрактов в Python
3.4. Анализ последовательностей методов (Method Sequence Analysis)
Идея: Дефекты состояния часто проявляются только при определённых последовательностях вызовов методов. Тестирование должно проверять не только отдельные методы, но и их комбинации.

Пример проблемной последовательности:

java
account.withdraw(100);  // OK: баланс 100
account.withdraw(50);   // OK: баланс 50
account.withdraw(100);  // Ошибка: недостаточно средств
// Состояние: баланс = 50, failedAttempts = 1
account.withdraw(30);   // OK: баланс 20
// Состояние: баланс = 20, failedAttempts = 0 (сброс после успешной операции)
Техника: Генерация случайных последовательностей вызовов и проверка состояния после каждой операции.

Подходы:

Случайное тестирование (Random Testing): Генерация случайных последовательностей и проверка инвариантов.

All-sequences тестирование: Проверка всех возможных последовательностей ограниченной длины.

Парное тестирование последовательностей (Pairwise Sequence Testing): Проверка всех пар последовательных вызовов.

3.5. Тестирование с использованием конечных автоматов (FSM-Based State Testing)
Идея: Если поведение объекта может быть описано конечным автоматом, то состояние объекта соответствует состоянию автомата. Тесты проверяют корректность переходов между состояниями.

Пример FSM для класса BankAccount:

text
[АКТИВНЫЙ] --withdraw(x)--> [АКТИВНЫЙ]  (если x <= balance)
[АКТИВНЫЙ] --withdraw(x)--> [ОШИБКА]    (если x > balance, попытка 1-2)
[ОШИБКА]   --withdraw(x)--> [ЗАБЛОКИРОВАН] (если попытка 3)
[ЗАБЛОКИРОВАН] --unblock()--> [АКТИВНЫЙ]
Связь с инвариантами: Каждое состояние автомата имеет свои инварианты, которые должны выполняться.

4. Методы реализации проверки состояния
4.1. Assertions (Утверждения)
Определение: Встроенный в язык механизм проверки условий во время выполнения.

Преимущества:

Простота использования.

Работает в продакшн-коде.

Может быть отключён для повышения производительности.

Недостатки:

Могут быть отключены, что снижает надёжность.

Не являются полноценным инструментом контрактного программирования.

Пример использования:

java
public void deposit(double amount) {
    assert amount > 0 : "amount must be positive";
    double oldBalance = balance;
    balance += amount;
    assert balance == oldBalance + amount : "balance update failed";
}

5. Полный пример: Тестирование класса BankAccount
5.1. Определение класса
java
public class BankAccount {
    private double balance;
    private boolean isBlocked;
    private int failedAttempts;
    private static final int MAX_FAILED_ATTEMPTS = 3;
    private static final double MAX_BALANCE = 1000000;
    
    public BankAccount(double initialBalance) {
        this.balance = initialBalance;
        this.isBlocked = false;
        this.failedAttempts = 0;
    }
    
    public void deposit(double amount) {
        if (amount <= 0) {
            throw new IllegalArgumentException("Amount must be positive");
        }
        if (balance + amount > MAX_BALANCE) {
            throw new IllegalStateException("Balance limit exceeded");
        }
        balance += amount;
        failedAttempts = 0; // Успешная операция сбрасывает счётчик
    }
    
    public void withdraw(double amount) {
        if (isBlocked) {
            throw new IllegalStateException("Account is blocked");
        }
        if (amount <= 0) {
            throw new IllegalArgumentException("Amount must be positive");
        }
        if (amount > balance) {
            failedAttempts++;
            if (failedAttempts >= MAX_FAILED_ATTEMPTS) {
                isBlocked = true;
            }
            throw new InsufficientFundsException("Insufficient funds");
        }
        balance -= amount;
        failedAttempts = 0;
    }
    
    public void unblock() {
        if (!isBlocked) {
            throw new IllegalStateException("Account is not blocked");
        }
        isBlocked = false;
        failedAttempts = 0;
    }
    
    // Getters
    public double getBalance() { return balance; }
    public boolean isBlocked() { return isBlocked; }
    public int getFailedAttempts() { return failedAttempts; }
}
5.2. Определение инвариантов
java
private void checkInvariants() {
    // Инвариант 1: баланс не отрицательный
    assert balance >= 0 : "Negative balance";
    
    // Инвариант 2: баланс не превышает лимит
    assert balance <= MAX_BALANCE : "Balance exceeds limit";
    
    // Инвариант 3: если заблокирован, то попыток >= 3
    if (isBlocked) {
        assert failedAttempts >= MAX_FAILED_ATTEMPTS : "Blocked with < 3 attempts";
    }
    
    // Инвариант 4: если попыток >= 3, то заблокирован
    if (failedAttempts >= MAX_FAILED_ATTEMPTS) {
        assert isBlocked : "3+ attempts but not blocked";
    }
    
    // Инвариант 5: попытки не отрицательные
    assert failedAttempts >= 0 : "Negative failed attempts";
}

5.4. Код тестов
java
@Test
public void testDepositState() {
    // State: начальное состояние
    BankAccount account = new BankAccount(1000);
    AccountSnapshot before = new AccountSnapshot(account);
    assertEquals(1000, before.getBalance());
    assertFalse(before.isBlocked());
    assertEquals(0, before.getFailedAttempts());
    
    // Action
    account.deposit(500);
    
    // State: конечное состояние
    AccountSnapshot after = new AccountSnapshot(account);
    assertEquals(1500, after.getBalance());
    assertFalse(after.isBlocked());
    assertEquals(0, after.getFailedAttempts());
    account.checkInvariants(); // Инварианты сохранены
}

@Test
public void testWithdrawWithInsufficientFunds() {
    BankAccount account = new BankAccount(1000);
    account.checkInvariants();
    
    // Первая неудачная попытка
    try {
        account.withdraw(1500);
        fail("Expected InsufficientFundsException");
    } catch (InsufficientFundsException e) {
        // Ожидаемое исключение
    }
    assertEquals(1000, account.getBalance());
    assertEquals(1, account.getFailedAttempts());
    assertFalse(account.isBlocked());
    account.checkInvariants();
    
    // Вторая неудачная попытка
    try {
        account.withdraw(1500);
    } catch (InsufficientFundsException e) {}
    assertEquals(1000, account.getBalance());
    assertEquals(2, account.getFailedAttempts());
    assertFalse(account.isBlocked());
    account.checkInvariants();
    
    // Третья неудачная попытка → блокировка
    try {
        account.withdraw(1500);
    } catch (InsufficientFundsException e) {}
    assertEquals(1000, account.getBalance());
    assertEquals(3, account.getFailedAttempts());
    assertTrue(account.isBlocked());
    account.checkInvariants(); // Инвариант 3 и 4 проверены
}
6. Распространённые ошибки при тестировании состояния
Ошибка	Описание	Решение
Проверка только возвращаемых значений	Тестируется только результат метода, а не состояние объекта.	Всегда проверяйте состояние до и после.
Игнорирование инвариантов	Инварианты не формализованы и не проверяются.	Специфицируйте инварианты и проверяйте их автоматически.
Неполная проверка состояния	Проверяются только некоторые поля.	Проверяйте все поля, влияющие на поведение.
Тестирование изолированно	Методы тестируются отдельно, без учёта последовательности.	Тестируйте последовательности и комбинации методов.
Отсутствие проверки исключительных состояний	Не проверяются состояния при ошибках.	Проверяйте состояние и после исключений.

8. Итоговый вывод по лекции
Тестирование состояния объектов — это не дополнительная опция, а необходимый компонент тестирования объектно-ориентированных систем.

Ключевые тезисы для запоминания:

Состояние объекта — это совокупность значений всех его полей в конкретный момент времени.

Инварианты класса — условия, которые должны быть истинны для всех корректных состояний объекта.

Тестирование состояния должно проверять не только результаты методов, но и корректность изменения состояния.

Техника "Состояние-Действие-Состояние" — стандартный паттерн для тестирования состояния.

Контрактное программирование (предусловия, постусловия, инварианты) помогает формализовать ожидания.

Каждый метод должен обеспечивать сохранение всех инвариантов класса.

Особое внимание следует уделять последовательностям вызовов и исключительным ситуациям.

Задание на семинар
Задание: Разработать и реализовать тесты состояния для класса ShoppingCart.

Описание класса:

java
public class ShoppingCart {
    private List<Item> items;
    private double totalPrice;
    private boolean isCheckedOut;
    private String couponCode;
    private double discount;
    
    public void addItem(Item item) { ... }
    public void removeItem(Item item) { ... }
    public void applyCoupon(String code) { ... }
    public void checkout() { ... }
    public double getTotal() { ... }
    public int getItemCount() { ... }
}
Инварианты:

totalPrice == sum(item.price * item.quantity)

totalPrice >= 0

Если isCheckedOut == true, то корзина не пуста

Если couponCode != null, то discount > 0

discount >= 0 и discount <= 1.0

Задания для студентов:

Идентификация инвариантов: Дополнить список инвариантов для класса.

Реализация проверки: Написать метод checkInvariants().

Тест-кейсы: Разработать тесты по технике "Состояние-Действие-Состояние":

Добавление товара.

Удаление товара.

Применение купона.

Оформление заказа.

Проверка состояния после исключительных ситуаций.

Проверка последовательностей: Разработать тест, проверяющий корректность состояния при последовательности из 4-5 действий.

Анализ: Какие состояния недостижимы? Какие инварианты могут быть нарушены при неправильной реализации?
