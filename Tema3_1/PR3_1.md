## 2. Теоретическая справка

**Попарное тестирование (Pairwise Testing)** — техника тест-дизайна, при которой тестовые наборы формируются таким образом, чтобы **каждая возможная пара значений любых двух параметров** встретилась хотя бы в одном тест-кейсе.

**Основная формула:**
- Полный перебор: `V1 * V2 * V3 * ... * Vn` тестов.
- Попарное тестирование: значительно меньше, обычно в пределах `O(V^2)`.

**Алгоритм построения (упрощённо):**
1. Выбрать параметр с наибольшим количеством значений (базовый).
2. Построить матрицу, последовательно добавляя остальные параметры.
3. Заполнять столбцы так, чтобы покрыть все пары с уже добавленными параметрами.
4. Использовать принцип "сдвига" для равномерного распределения значений.

### 5.1. Исходные данные

### 5.3. Построение матрицы попарного тестирования

#### Шаг 1. Выбор базового параметра

Выбираем параметр с максимальным количеством значений. У нас два параметра по 3 значения (Тип и Язык). Возьмем **Тип пользователя** (Т).

Покрываем пары:
- (Т1-С1,С2,С3), (Т2-С1,С2), (Т3-С1,С2,С3)
- (Я1-С1,С2,С3), (Я2-С1,С2,С3), (Я3-С1,С2,С3)

### 5.4. Фильтрация невалидных комбинаций

Согласно условию, для Юридического лица способ "QR" недоступен.

- Строка 7: Физ + Каз + QR (оставляем, так как Физ лицо может иметь QR)

## 6. Требования к отчёту

Отчёт должен содержать следующие разделы:

1. **Титульный лист** (с указанием дисциплины, группы, ФИО, варианта).
2. **Цель работы**.
3. **Исходные данные** (таблица параметров и значений из варианта).
4. **Расчёт полного перебора** (количество тестов при исчерпывающем тестировании).
5. **Матрица попарного тестирования** (пошаговое построение).
6. **Фильтрация невалидных комбинаций** (если есть ограничения).
7. **Итоговый набор тест-кейсов** (в виде таблицы с номерами и ожидаемыми результатами — кратко).
8. **Оценка эффективности** (сравнение количества тестов).
9. **Вывод** (что дало применение техники, её преимущества и ограничения в данном конкретном случае).
