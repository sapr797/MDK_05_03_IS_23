## 2. Теоретическая справка

### 2.1. Баг-трекинговая система

**Баг-трекинговая система** — это инструмент для регистрации, отслеживания и управления дефектами в процессе разработки ПО.

**Основные элементы:**
- **Issue** (задача/баг) — единица работы.
- **Статусы** — жизненный цикл дефекта.
- **Атрибуты** — заголовок, описание, приоритет, серьёзность, компонент, версия.
- **Комментарии** — обсуждение дефекта.
- **Приложения** — скриншоты, логи, видео.

### 2.2. Классификация дефектов

**По серьёзности (Severity):**

| Уровень | Описание | Пример |
|---------|----------|--------|
| **Blocker** | Блокирует дальнейшую работу | Приложение падает при запуске |
| **Critical** | Критическая ошибка, нет обходного пути | Не работает основная функция |
| **Major** | Значительная ошибка, есть обходной путь | Неправильный расчёт, но можно исправить вручную |
| **Minor** | Незначительная ошибка | Неправильный цвет кнопки |
| **Trivial** | Косметический дефект | Опечатка в тексте |

**По приоритету (Priority):**

| Уровень | Описание | Пример |
|---------|----------|--------|
| **P1** | Нужно исправить немедленно | Сбой в production |
| **P2** | Исправить в ближайшем релизе | Ошибка в новом функционале |
| **P3** | Исправить, когда будет время | Мелкие баги без влияния |
| **P4** | Исправить в следующем релизе | Незначительные улучшения |

### 2.3. Метрики дефектов

| Метрика | Формула | Назначение |
|---------|---------|------------|
| **Общее количество дефектов** | Сумма всех багов | Общая оценка качества |
| **Плотность дефектов** | Дефекты / LOC | Качество кода |
| **Скорость обнаружения** | Баги в день | Эффективность тестирования |
| **Скорость закрытия** | Закрытые баги в день | Эффективность разработки |
| **% критических багов** | Критические / Все | Риски релиза |
| **Среднее время жизни** | Суммарное время / Количество | Процесс исправления |
| **Retest Rate** | Переоткрытые / Все | Качество фиксов |

**Сценарий:** Вы тестируете интернет-магазин электроники. В ходе тестирования обнаружены следующие дефекты:

| № | Описание бага | Компонент | Шаги воспроизведения |
|---|---------------|-----------|----------------------|

| 2 | Неправильный расчёт суммы со скидкой | Корзина | 1. Добавить товар за 1000 ₽ → 2. Применить промокод "SUMMER" (скидка 15%) → 3. Итоговая сумма = 950 ₽ (должно быть 850 ₽) |
| 3 | Товар не отображается в каталоге после публикации | Каталог | 1. Создать товар в админке → 2. Опубликовать → 3. На странице каталога товар отсутствует |
| 4 | Кнопка "Оплатить" неактивна на странице оформления | Оплата | 1. Заполнить все поля формы → 2. Кнопка "Оплатить" остаётся серой |
| 5 | Неправильное отображение цены на мобильных устройствах | UI | 1. Открыть сайт на iPhone 12 → 2. Цена отображается в $ вместо ₽ |
| 6 | Опечатка в тексте "Доставка" на главной странице | Контент | Отображается "Доставкаа" вместо "Доставка" |
| 7 | Не сохраняются настройки пользователя в личном кабинете | ЛК | 1. Изменить телефон в профиле → 2. Сохранить → 3. При перезагрузке телефон сбрасывается |
| 8 | Заказ не создаётся при выборе доставки курьером | Заказы | 1. Оформить заказ → 2. Выбрать доставку курьером → 3. Ошибка "Нет доступных курьеров" |
| 9 | Промокод применяется повторно после отмены заказа | Корзина | 1. Применить промокод → 2. Отменить заказ → 3. Создать новый заказ → 4. Промокод применяется автоматически |
| 10 | Не отображается статус заказа после оплаты | Заказы | 1. Оплатить заказ → 2. Статус остаётся "Ожидает оплаты" |

**Задания:**

1. **Регистрация багов:** Заполнить форму баг-репорта для каждого дефекта:
   - Заголовок
   - Описание
   - Шаги воспроизведения
   - Ожидаемый результат
   - Фактический результат
   - Приоритет (P1-P4)
   - Серьёзность (Blocker-Critical-Major-Minor-Trivial)
   - Компонент
   - Статус (NEW)

2. **Классификация:** Распределить баги по категориям:
   - Функциональные / UI / Производительность / Контент
   - Критические / Основные / Второстепенные

3. **Метрики:** Рассчитать метрики дефектов:
   - Общее количество дефектов по компонентам
   - Количество критических багов
   - % багов по серьёзности
   - Среднее время жизни (по дням — гипотетически)

4. **Отчёт:** Составить отчёт о тестировании:
   - Цель тестирования
   - Объём тестирования
   - Результаты (пройдено/провалено)
   - Список найденных дефектов
   - Рекомендации

5. **Анализ:** На основе метрик сделать выводы:
   - Какие компоненты самые проблемные?
   - Какие баги нужно исправить в первую очередь?
   - Готов ли продукт к релизу?
